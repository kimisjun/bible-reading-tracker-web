# Wave 3 통독 계획 공통 계약

## 목적

계획 생성 엔진, 놓친 일정 처리, 저장 계층, 설정 UI가 같은 타입과 날짜 의미를 사용하도록 고정한다. 이 문서와 `src/domain/planTypes.ts`가 Wave 3의 권위 있는 계약이다.

## 날짜 규칙

- 모든 계획 날짜는 기기 로컬 달력의 `YYYY-MM-DD` 문자열이다.
- 시작일과 종료일은 모두 포함한다.
- 요일 번호는 JavaScript `Date#getDay()`와 동일하게 `0=일요일`부터 `6=토요일`이다.
- 엔진은 UTC 시각으로 날짜를 바꾸지 않는다.
- 존재하지 않는 날짜, 종료일이 시작일보다 이른 기간, 빈 요일 선택은 거부한다.

## 계획 요청

- 종류: 교회 공통 계획 `common` 또는 개인 계획 `personal`
- 범위:
  - `all`: 성경 전체
  - `old`: 구약
  - `new`: 신약
  - `books`: 사용자가 고른 책 목록
- 읽기 순서:
  - `canonical`: 66권 정경 순서
  - `old-new-parallel`: 구약 한 장, 신약 한 장을 번갈아 배치하고 한쪽이 끝나면 나머지를 이어 붙임
- 놓친 일정 정책:
  - `carry`: 오늘 분량 앞에 과거 미완료 분량을 누적하며 미래 일정은 유지
  - `redistribute`: 완료 장은 고정하고 미완료 장을 오늘부터 기존 종료일까지 남은 읽는 날에 균등 재배분
  - `restart-today`: 완료 장은 고정하고 미완료 장을 오늘부터 원래 계획 전체와 같은 수의 읽는 날에 다시 배분하여 종료일을 뒤로 이동 가능

## 기본 기간

- `one-year`: 시작일부터 다음 해 같은 날짜 직전까지
- `six-month`: 시작일에서 6개월 뒤 같은 날짜 직전까지
- `ninety-days`: 시작일 포함 90일
- 월말 계산은 JavaScript 자동 보정이 아니라 해당 월의 유효한 마지막 날짜로 고정한다.

## 일정 생성 규칙

1. 범위를 장 단위 목록으로 만든다.
2. 읽기 순서를 적용한다.
3. 기간 안에서 선택한 요일만 읽는 날로 선택한다.
4. 모든 장을 정확히 한 번 배치한다.
5. 읽는 날별 장 수 차이는 최대 1장이다.
6. 나머지 장은 앞쪽 읽는 날부터 한 장씩 더 배치한다.
7. 읽는 날이 없거나 범위가 비어 있으면 구체적인 오류를 반환한다.

## 완료 판단

- 계획 자체에 완료 플래그를 원본으로 저장하지 않는다.
- 완료 여부는 `ReadingEvent` 합계가 1 이상인 장 집합을 입력으로 받아 파생한다.
- 재계산은 완료된 장을 다시 일정에 넣지 않는다.
- 완료 이벤트를 삭제하지 않고 기존 이벤트 로그를 유지한다.

## 저장 계약

- `commonPlan`과 `personalPlan`은 각각 최대 하나다.
- 계획에는 요청, 생성 일정, 생성 시각을 저장한다.
- 저장소 런타임 검증은 날짜·요일·책·장·중복 장·일정 범위를 확인한다.
- 기존 `schemaVersion: 1`의 `null` 계획은 그대로 호환한다.
- 임의 객체 형태의 과거 계획은 사용자 기록을 조용히 삭제하지 않고 명확한 오류로 처리한다.

## UI 계약

- 저장 전 총 장 수, 읽는 날 수, 하루 평균, 첫 7일을 미리 보여준다.
- 하루 10장 이상이면 경고하되 저장을 막지 않는다.
- 공통 계획 1개와 개인 계획 1개를 동시에 표시할 수 있다.
- 계획 선택을 최초 방문에 강제하지 않는다.
