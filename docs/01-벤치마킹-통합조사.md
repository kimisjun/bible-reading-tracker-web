# 성경통독 웹앱 벤치마킹 통합 조사

- 조사일: 2026-07-30
- 목적: 아산제일교회 교인과 고령 성도가 함께 사용하는 계정형 성경통독 웹앱 설계
- 범위: 독서 기록 앱, 성경 통독 앱, 교육·습관 앱, GitHub 오픈소스
- 상태: 설계 조사 단계. 개발 미착수

## 1. 핵심 결론

우리 앱은 아래 네 가지 장점을 조합하는 것이 가장 적합하다.

1. **Read Scripture·Duolingo의 한 줄 경로**
   - 로그인하면 오늘 할 한 가지를 바로 보여 준다.
   - 다음 행동을 고민하지 않게 한다.

2. **Bookmory·StoryGraph의 간단한 기록과 회고**
   - 읽은 장을 큰 버튼으로 누른다.
   - 월 달력에서 완료·일부 읽음·쉼을 쉽게 확인한다.

3. **YouVersion의 계정 동기화와 계획 구조**
   - 휴대전화 번호 기반 계정으로 여러 기기에서 이어서 사용한다.
   - 자유 통독 기록과 계획별 완료 기록을 분리한다.

4. **Beanstack의 공동체·관리자 구조**
   - 성도 화면은 단순하게 유지한다.
   - 교역자·관리자 화면은 별도로 두고 참여 현황과 계정 지원만 제공한다.
   - 개인 순위 대신 교회·소그룹 공동 목표를 사용한다.

## 3. 우리 앱의 권장 제품 구조

### 3.1 개인 성도 화면

첫 화면의 주요 행동은 세 개 이내로 제한한다.

1. **오늘 읽기**
2. **성경 전체 통독표**
3. **나의 진행 현황**

첫 화면 예시:

```text
김성도님, 오늘도 말씀과 함께 걸어요

오늘 읽기
누가복음 5–6장
[본문 보기]  [읽었어요]

이번 주 4일 함께했어요
전체 328 / 1,189장
[통독표 전체 보기]
```

### 3.2 통독 기록을 두 종류로 분리

- **성경 장 마스터 기록:** 창세기 1장을 읽었는지 여부. 1,189장 전체 지도에 반영한다.
- **통독 계획 기록:** 특정 계획의 12일 차를 완료했는지 여부.

같은 장을 여러 계획에서 읽더라도 전체 장 지도와 계획 완료는 각각 독립적으로 기록한다.

### 3.3 공동체 화면

- 교회 전체 또는 소그룹의 누적 읽은 장 수
- 함께 완주한 인원 수
- 정해진 문구로 응원하기
- 개인 순위는 표시하지 않음
- 개인의 상세 장 기록과 묵상 메모는 기본 비공개

### 3.4 관리자 화면

- 교인 계정 생성·휴대전화 번호 변경·비밀번호 재설정
- 전체 가입·활성 사용자 수
- 익명 또는 동의 범위 내 주간 참여 추세
- 소그룹 생성과 구성원 배정
- 교회 통독 계획 개설
- 장기간 기록이 없는 교인에 대한 지원 목록은 본인 동의를 받은 경우만 제공
- 성도의 신앙 수준을 점수화하거나 순위를 만들지 않음

## 4. 동기부여 정책

### 적용

- 하루 연속일보다 **이번 주 3/5일** 같은 유연 목표
- 아프거나 여행한 날을 위한 **쉼·은혜일**
- 놓친 뒤 돌아오면 **다시 시작한 날**을 축하
- 창세기·복음서·신약 등 의미 있는 마일스톤
- 개인 기록과 공동체 누적 목표
- 차분한 축하 문구

### 제외

- 개인 리더보드와 교회 내 순위
- 하루 누락 시 모든 연속 기록을 0으로 초기화
- 빨간 실패 화면, 벌점, 체력 감소
- 보석·유료 재화·확률형 보상
- 반복적인 죄책감 알림
- 읽기 속도와 양으로 신앙을 평가하는 표현

## 5. 고령 성도 접근성 원칙

- 본문 외 UI 기본 글자 18–20px 이상
- 모든 주요 터치 영역 최소 44×44px, 권장 48px
- 큰 글자 버튼을 첫 화면에 상시 제공
- 완료 상태를 색상뿐 아니라 체크 아이콘과 ‘완료’ 글자로 표시
- 화면당 핵심 과업 한 개
- 스와이프 전용 기능 금지
- 쉬운 한국어와 짧은 문장
- 읽기·듣기 속도 조절과 0.75배속 고려
- 알림은 기본 하루 1회 이하, 쉽게 미루거나 끌 수 있게 함
- 키보드, TalkBack, VoiceOver, 200% 확대 검증
- 실제 60–80대 성도 5–8명으로 사용성 시험

### 권장 방침

- 특정 앱을 그대로 포크하지 않고 **새 웹앱으로 독립 구현**한다.
- MIT·Apache 계열 프로젝트의 구조와 아이디어를 우선 참고한다.
- GPL·AGPL 프로젝트는 코드 복사 전에 공개 의무를 별도 검토한다.
- 오픈소스 코드 라이선스와 성경 본문 저작권을 별개로 판단한다.

## 7. 성경 본문 저작권 원칙

- 앱 코드가 오픈소스여도 개역개정·새번역 등 성경 번역문 사용권은 자동으로 확보되지 않는다.
- 텍스트, 오디오, 묵상, 영상은 각각 별도 권리다.
- GitHub 저장소에 들어 있는 성경 JSON·DB라고 해서 합법적으로 재배포할 수 있는 것은 아니다.
- 초기 버전은 다음 중 하나가 안전하다.
  1. 본문 없이 장별 체크와 통독 계획만 제공
  2. 정식 허가를 받은 API 또는 번역본 사용
  3. 외부 공식 성경 서비스의 해당 장으로 연결
- 앱 내부에는 `BibleTextProvider`라는 별도 공급 계층을 두어, 통독 기록과 본문 라이선스를 분리한다.

## 8. 기능 우선순위 제안

### 1차 핵심

- 휴대전화 번호 + 비밀번호 로그인
- 오늘 읽기
- 66권·1,189장 큰 체크표
- 권별 10회 완독 열매
- 전체·구약·신약 진행률
- 여러 기기 동기화
- 큰 글자·고대비·쉬운 조작
- 유연한 주간 목표와 알림

### 2차

- 월간 통독 달력
- 교회·소그룹 공동 목표
- 정형화된 응원
- 관리자 계정 지원·통계
- 오프라인 임시 저장 후 재연결 동기화

### 3차

- 정식 라이선스 본문과 오디오
- 마음에 남은 말씀·음성 메모
- 교회가 검수한 책 개관 자료
- 과거 말씀 회고와 선택형 복습

## 9. 다음 설계 결정

자료 조사 후 가장 먼저 정해야 할 것은 앱의 중심 사용 방식이다.

- 자유 통독표 중심
- 매일 정해진 계획 중심
- 오늘 계획과 자유 통독표를 함께 제공하는 혼합형

조사 결과로는 **혼합형**이 가장 적합하다. 첫 화면은 오늘 계획으로 단순하게 유지하고, 전체 통독표에서는 언제든 자유롭게 장을 기록할 수 있다.
