# 다중 에이전트 협업 규칙

## 목적

여러 에이전트가 같은 기능이나 파일을 중복 수정하지 않고 독립적으로 개발한 뒤 안전하게 통합하기 위한 규칙이다.

## 역할

- **통합자:** `master` 관리, 작업 분배, 계약 조정, cherry-pick, 전체 검증, 배포
- **기능 에이전트:** 지정된 worktree·브랜치·파일 범위에서 TDD 구현
- **검토 에이전트:** 구현 후 요구사항·보안·접근성·테스트 누락 검토

## 작업 수락 전에 확인할 것

1. `git status -sb`가 깨끗한가
2. 현재 브랜치가 지정 브랜치인가
3. 수정 허용 범위가 명확한가
4. 기존 도메인 타입과 테스트 명령을 읽었는가
5. 다른 에이전트 작업에 선행 의존성이 없는가

## 구현 규칙

1. 하나의 사용자 행동을 나타내는 실패 테스트를 먼저 작성한다.
2. 테스트가 기능 부재 때문에 실패하는 것을 실제 출력으로 확인한다.
3. 최소 구현으로 집중 테스트를 통과시킨다.
4. 전체 테스트와 빌드를 실행한다.
5. 작업 범위 밖 파일은 수정하지 않는다.
6. 하나의 독립 기능 단위로 커밋한다.

## 공통 계약

- `ReadingEvent`는 `src/domain/reading.ts`의 타입을 재사용한다.
- 성경 메타데이터는 `src/data/bibleBooks.ts`를 단일 출처로 사용한다.
- 진행률은 반복 합계가 아니라 1회 이상 읽은 고유 장 수를 기준으로 한다.
- 읽기 이벤트는 삭제하지 않고 반대 이벤트로 취소한다.
- 시간은 저장 시 ISO 8601 문자열, 화면 표시 시 기기 로컬 시간으로 처리한다.
- 사용자 데이터는 브라우저 저장소에 버전과 함께 저장한다.
- UI 터치 영역은 최소 44px이고 완료 상태는 색상 외 텍스트·아이콘으로도 표시한다.

## 에이전트 완료 보고 형식

```text
worktree: <절대 경로>
branch: <브랜치>
commit: <SHA>
changed: <파일 목록>
RED: <실패 명령과 기대한 실패 이유>
GREEN: <집중 테스트 결과>
FULL: <전체 테스트/빌드 결과>
risks: <남은 위험 또는 none>
```
