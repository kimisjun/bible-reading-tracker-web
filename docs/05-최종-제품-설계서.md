# 말씀과 함께 걷기 — 최종 제품 설계서

- 문서 상태: 개발 승인 대기
- 제품 대상: 아산제일교회 교인, 고령 성도, 교회 관리자
- 기존 서비스: 로그인 없는 개인 오프라인 웹앱
- 목표 서비스: 개인 오프라인 사용성을 보존하며 계정·다기기 동기화·교회 공동 계획을 지원하는 웹/PWA

## 1. 제품 목표

교인이 휴대전화·태블릿·PC에서 성경 읽기를 쉽고 꾸준히 기록하도록 돕는다.

핵심 질문에 첫 화면이 즉시 답해야 한다.

1. 오늘 무엇을 읽으면 되는가?
2. 오늘 몇 장을 읽었는가?
3. 이번 주 월요일부터 일요일까지 몇 장을 읽었는가?
4. 성경 1,189장 중 몇 장을 한 번 이상 읽었는가?
5. 다음에는 어디서 이어서 읽으면 되는가?

읽기 분량으로 신앙을 평가하거나 성도끼리 경쟁시키지 않는다.

## 2. 확정된 제품 원칙

- 오늘 계획과 자유 통독표를 함께 제공하는 혼합형
- 휴대전화 번호 + 비밀번호 로그인
- 개인별 일회용 교회 초대코드
- 어려운 성도는 관리자가 계정을 대신 발급
- 역할은 성도·관리자 2단계
- 관리자 기본 화면은 개인 상세가 아닌 전체 집계
- 개인 기록은 성도 동의와 만료 기간이 있어야 관리자 열람 가능
- 한국 시간, 월요일 시작·일요일 종료 주간 집계
- 전체 고유 장 진도와 실제 반복 읽기 통독량 분리
- 기존 개인 오프라인판과 기록 보존
- 성경 번역문·오디오를 저장소에 포함하지 않음
- 개인 순위·벌점·연속일 초기화·신앙 점수 제외

## 3. 사용자 유형

### 성도

- 디지털 기기에 익숙한 일반 성도
- 큰 글자와 단순한 조작이 필요한 고령 성도
- 한 기기만 사용하는 성도
- 휴대전화와 PC 등 여러 기기에서 이어 쓰는 성도

### 관리자

- 성도 계정 생성·복구를 지원하는 교회 담당자
- 교회 공통 통독 계획과 공지를 운영하는 담당자
- 개인 평가가 아니라 익명 공동체 참여 현황을 확인하는 담당자

## 4. 정보 구조

모바일 하단 메뉴는 다섯 개로 제한한다.

1. **오늘** — 오늘 계획, 오늘 통독량, 이번 주 통독량, 전체 진도
2. **통독표** — 성경 66권·1,189장, 반복 읽기, 권별 10회 완독 열매
3. **진행** — 월간 달력, 기간별 합계, 최근 기록, 계획 진행
4. **함께** — 교회 공동 목표, 공통 계획, 정형화된 격려
5. **설정** — 계정, 알림, 큰 글자, 개인정보, 백업, 로그아웃

관리자 화면은 별도 `/admin` 경로로 분리한다.

## 5. 오늘 첫 페이지

### 화면 우선순위

1. 오늘 읽을 분량과 큰 `읽었어요` 버튼
2. 오늘 읽은 장 수
3. 월–일 요일별 통독량과 이번 주 총합
4. 전체·구약·신약 고유 장 진도
5. 전체 통독표와 최근 기록으로 이동

### 모바일 예시

```text
김성도님, 오늘도 말씀과 함께 걸어요
2026년 7월 30일 목요일

[오늘 읽기]
누가복음 5–6장 · 2장
[말씀 보기] [읽었어요]
[일부만 읽었어요] [오늘은 쉬어요]

[오늘 읽은 분량]
4장
계획 2장 + 자유 통독 2장

[이번 주 통독]
월 3 · 화 5 · 수 6 · 목 4 · 금 - · 토 - · 일 -
이번 주 총 18장

[전체 통독 진도]
328 / 1,189장 · 27.6%
[성경 66권 통독표]
```

## 6. 통독량 계산 규칙

### 전체 진도

- 유효한 읽기 이벤트가 한 번 이상 있는 고유 장 수
- 최대 1,189장, 100%
- 반복 읽기로 증가하지 않음

### 오늘 통독량

- 한국 시간 오늘 생성된 유효한 READ 이벤트의 장 수
- 계획·자유 통독·명시적 다시 읽기를 모두 포함
- 취소된 이벤트와 중복 재전송 제외

### 주간 통독량

- 한국 시간 월요일 00:00부터 일요일 23:59까지
- 월·화·수·목·금·토·일의 일일 통독량과 총합 표시
- 미래 요일은 `-`, 지난 무기록 요일은 `0`
- 오프라인 미동기화 기록이 있으면 `동기화 대기 포함` 표시

### 반복 읽기

- 이미 읽은 장을 다시 읽었을 때 `다시 읽음`을 명시적으로 선택
- 전체 진도에는 추가되지 않음
- 오늘·주간 통독량과 장별 읽은 횟수에는 추가

## 7. 기록 데이터 원칙

합계가 아니라 ReadingEvent를 원본으로 저장한다.

```text
ReadingEvent
- id
- userId
- deviceId
- bookId
- chapterNumber
- action: READ | CANCEL
- source: DAILY_PLAN | FREE_READING | REREAD | IMPORT
- planAssignmentId
- groupId
- occurredAt
- receivedAt
- timezone
- targetEventId
- idempotencyKey
```

- 기록은 물리 삭제하지 않고 CANCEL 이벤트로 취소
- 같은 요청의 재전송은 idempotencyKey로 한 번만 반영
- 전체·오늘·주간·월간 합계를 원장 이벤트에서 재계산 가능
- 기존 앱의 ReadingEvent 개념을 유지해 마이그레이션 비용을 줄임

## 8. 통독 계획

### 교회 공통 계획

- 관리자가 생성·게시
- 1년·6개월·90일 템플릿
- 전체·구약·신약·복음서 등 범위
- 월–일 읽는 요일 선택
- 계획의 오늘 분량과 장별 완료

### 개인 계획

- 성도가 범위·기간·읽는 요일 선택
- 성경 순서 또는 구약·신약 병행
- 놓친 일정 처리:
  1. 밀린 분량 누적
  2. 남은 날짜에 재분배
  3. 오늘부터 다시 계산

### 자유 통독

- 계획과 관계없이 통독표에서 어떤 장이든 기록
- 자유 기록도 오늘·주간 통독량과 전체 진도에 반영

## 9. 권별 10회 완독 열매

- 각 권의 모든 장이 최소 한 번씩 추가로 읽힌 회차를 계산하는 자동 방식과 수동 확인 방식을 비교 검증
- 1차 서버판은 기존 사용자 경험을 보존해 최대 10회 수동 열매를 지원
- 각 열매에는 완료 날짜 기록
- 열매를 취소할 수 있으며 감사 가능한 이벤트로 남김
- 전체 장별 읽기 횟수와 열매 수가 불일치하면 안내하고 사용자가 확인

## 10. 계정과 가입

### 가입

1. 관리자가 개인별 일회용 초대코드 발급
2. 성도가 초대코드·이름·휴대전화 번호·비밀번호 입력
3. 서버 검증 후 계정 생성
4. 개인정보 공유 기본값 비공개 확인
5. 큰 글자·알림 시간 선택

### 관리자 대행

- 본인 확인 후 계정 생성
- 임시 비밀번호 발급
- 첫 로그인에서 비밀번호 변경 강제

### 비밀번호 복구

- 초기에는 관리자 본인 확인 후 초기화
- 기존 세션 전체 로그아웃
- 향후 국내 SMS 인증을 선택적으로 추가

## 13. 접근성

- 기본 UI 글자 18–20px 이상
- 주요 터치 영역 최소 44px, 권장 48px
- 첫 화면의 `큰 글자` 즉시 전환
- 색상+체크+텍스트로 상태 중복 표현
- 200% 확대 시 가로 스크롤 없이 재배치
- 키보드·TalkBack·VoiceOver 지원
- 스와이프 전용 기능 금지
- 자동 재생·시간 제한 금지
- 쉬운 한국어와 한 화면 한 과업
- 실제 60–80대 성도 5–8명 사용성 시험

## 14. 기술 아키텍처

### 프런트엔드

- 기존 React + TypeScript + Vite 유지
- PWA와 서비스 워커
- IndexedDB 오프라인 이벤트 원장·Outbox
- 즉시 로컬 반영 후 서버 동기화

### 백엔드 권장안

- 관리형 PostgreSQL·인증·서버 함수
- Supabase 계열을 1차 후보로 기술 검증
- Row Level Security로 본인 데이터만 조회
- 관리자 동작은 서버 함수와 감사 로그 필수
- 관리자 집계 API는 개인 식별 정보 제거

### 배포

- 기존 개인판 GitHub Pages 유지
- 계정형 서버판은 별도 시험 주소와 운영 주소
- 예: `bible.asanjeil.org`
- 개발·시험·운영 환경 분리
- GitHub Pages에 비밀 키·관리자 로직·DB를 두지 않음

## 15. 오프라인·동기화

1. 장 기록을 IndexedDB에 즉시 저장
2. Outbox에 전송 대기
3. 온라인 복귀 시 서버로 전송
4. UUID·idempotencyKey로 중복 제거
5. 성공 시 `저장됨`
6. 미전송 시 `동기화 대기`
7. 인증·검증 오류 시 `확인 필요`

두 기기의 읽기 이벤트는 합치고, 취소 이벤트를 원본 ID에 적용한다. 주간 합계와 진도는 서버에서 다시 계산한다.

## 16. 본문·저작권

- 성경 번역문과 오디오를 저장소·DB에 넣지 않음
- 초기에는 대한성서공회 등 정식 서비스의 장별 페이지로 연결
- 본문 제공 계층을 통독 기록과 분리
- 향후 정식 라이선스 API 계약 시에만 앱 내부 본문 제공
- 오픈소스 코드 라이선스와 성경 번역문 권리를 별도 검토
